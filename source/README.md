# YaGo

Нативный клиент Яндекс Музыки на Go. Прототипы Windows и Android.

## Яндекс и Звук — 0.10.0

Windows и Android: отдельные профили, общий поиск, любимое, история и плейлисты. Режим «Все» смешивает персональные волны; «Только Яндекс» и «Только Звук» разделяют библиотеки. Общие выпадающие настройки языка и настроения применяются к обоим сервисам; следующие треки обновляются в фоне, текущий продолжает играть. Несовместимые параметры остаются у своего сервиса.

На Android вход в Звук проходит в отдельном временном окне, токен получается автоматически. Вход Яндекса сохраняет прежний зашифрованный ключ; данные Звука хранятся отдельно через Android Keystore. Окно входа и его процесс завершаются после входа/отмены. Подробности: [ANDROID_0.10.0.md](ANDROID_0.10.0.md).

## Android

Файл: **`YaGo-android.apk`**, Android **8.0+** и OpenGL ES 3.0, ARM64 и ARMv7 в одном APK. Идентификатор `com.yago.mobile`, версия `0.11.11`. Подробная проверка — `ANDROID_VERIFICATION.md`.

Установите APK на телефон. Откройте **Профили**, подключите Яндекс по коду или Звук в окне входа. Вернитесь в YaGo. Уведомления нужны для удобного управления музыкой. Кнопки громкости телефона управляют громкостью музыки.

Добавлены телефонный интерфейс, Android Keystore (AES-GCM), фоновая служба воспроизведения, MediaSession, кнопки в уведомлении, обработка аудиофокуса и отключения наушников. Очередь работает отдельно от перерисовки окна. Сворачивание через «Назад» оставляет приложение в фоне; удаление приложения из списка недавних останавливает музыку.

APK подписан сохранённым локальным тестовым ключом. Он пригоден для ручной установки, а не является публикацией в магазине. Подпись v2/v3, manifest, обе ABI и выравнивание ELF 16 КиБ проверены. Запуск на настоящем Android-телефоне подтверждён пользователем. Портретная компоновка осмотрена в Windows-предпросмотре 380×820.

Сборка с уже подготовленными локальными инструментами:

```powershell
rtk proxy powershell -NoProfile -ExecutionPolicy Bypass -File ./build-android-native.ps1
rtk proxy powershell -NoProfile -ExecutionPolicy Bypass -File ./package-android.ps1
rtk proxy powershell -NoProfile -ExecutionPolicy Bypass -File ./verify-android.ps1
```

JDK 17, SDK 35, build-tools 35.0.0 и NDK r27c находятся внутри `.tools`. `setup-android.ps1` распаковывает исходные официальные архивы, если их загрузить заново. Проверенные при установке SHA Google-архивов записаны в скрипте; JDK SHA256 сверен с API Adoptium. Ключ `.tools/android-signing/yago-test.keystore` сохранён для установки обновлений поверх этой версии. Не удаляйте ключ при очистке.

## Запуск

Откройте `YaGo.exe`. Откройте **Профили → Подключить Яндекс**, затем **Открыть страницу входа**. Введите показанный код на `https://ya.ru/device`. Пароль приложение не получает. Полные треки требуют подписки Плюс.

Аккаунты подключаются через «Профили». Гостевой режим с фрагментами удалён.

## Возможности

- Авторизация по коду устройства; восстановление входа и обновление токена при запуске.
- Поиск треков, любимые треки, собственные плейлисты.
- «Моя волна», очередь, следующий/предыдущий трек, добавление текущего трека в любимые.
- MP3: старт до полной загрузки, пауза, перемотка по 15 секунд, громкость.
- Оконный интерфейс Gio; воспроизведение без Chromium, Electron и WebView. Android WebView используется только во временном отдельном процессе входа в Звук.
- Токены в системном хранилище: Windows Credential Manager, macOS Keychain, Linux Secret Service, Android Keystore. Если хранилище недоступно, вход живёт только до закрытия приложения.

## Память и аудио

Сжатый звук поступает во временный файл `state/audio`, а не целиком в оперативную память. Сетевой буфер — 64 КиБ; PCM-буфер плеера — около 250 мс. Один файл ограничен 256 МиБ. Файл удаляется при остановке, смене трека или штатном закрытии. После аварийного завершения остатки могут сохраниться.

После загрузки перемотка использует индекс MP3. Пока загрузка идёт, перемотка декодирует начало заново; на длинных записях это медленнее.

`state/metrics.json` содержит локальный замер собственного процесса каждые 5 секунд: Go heap, working set, private bytes, процессорное время. Эти сведения никуда не отправляются. Working set и Private Bytes — разные показатели; с показателями Rust-клиента следует сравнивать одинаковый сценарий и одинаковую метрику.

## Сборка Windows

Проверка окна входа в Звук из EXE с GUI-подсистемой:
`rtk proxy powershell -NoProfile -ExecutionPolicy Bypass -File ./verify-login-windows.ps1`.
Команда открывает отдельный временный браузер, проверяет обычное состояние окна,
через восемь секунд отменяет сессию и проверяет очистку профиля. Вход в аккаунт
не выполняется. Обычные `go test` не заменяют эту проверку перед выпуском Windows.

Для этого чата Go 1.27.4 установлен внутри `.tools/go`; зависимости и кэш также находятся в `.tools`. Системный PATH не менялся. Релиз 0.6.1 применяет воспроизводимую правку локального Go 1.27.4: crypto scratch buffer выделяется по необходимости. Скрипт prepare-toolchain.ps1 вызывается автоматически из go.ps1 и android-env.ps1. Подробности и проверки: [MEMORY_INVESTIGATION.md](MEMORY_INVESTIGATION.md), [toolchain-patches/README.md](toolchain-patches/README.md).

Из папки проекта:

```powershell
rtk proxy powershell -NoProfile -ExecutionPolicy Bypass -File ./build.ps1
rtk proxy powershell -NoProfile -ExecutionPolicy Bypass -File ./verify.ps1
rtk proxy powershell -NoProfile -ExecutionPolicy Bypass -File ./go.ps1 vet ./...
```

`verify.ps1` включает проверки реального MP3 и аудиоустройства с нулевой громкостью. Использует тестовый MP3 из модуля go-mp3. Обычный `go test ./...` без `YAGO_TEST_MP3` пропускает эти две интеграционные проверки.

Если локальных инструментов нет: используйте установленный Go 1.27+ и `go build -trimpath -ldflags="-s -w -H=windowsgui" -o YaGo.exe .`. Модули зафиксированы в `go.mod` и `go.sum`.

Сетевые запросы Яндекса, Звука и аудио используют `tls-client` с профилем Chrome 154 для TLS и HTTP/2. Проверка сертификатов, правила перенаправлений и разделение токенов API и запросов CDN сохранены. Android собирается прежними скриптами с Go 1.27.4; после изменения зависимостей требуется заново собрать нативные библиотеки ARM64 и ARMv7 и упаковать APK.

## Другие ОС

Исходники ориентированы на Windows, Linux и macOS. В этом сеансе запущено и проверено окно **только Windows x64**. Пакеты API, аудио и хранилища проходят перекрёстную компиляцию для Linux/macOS amd64. Это не заменяет проверку окна, системного звука и хранилища на этих ОС.

Gio на Linux/macOS требует нативных библиотек и C-компилятора. В `.github/workflows/build.yml` подготовлена матрица нативных сборок трёх ОС; workflow здесь не запускался. Windows собирается без CGO и отдельного C-компилятора.

## Проверенные ограничения

- Полный вход в пользовательский аккаунт и прослушивание защищённого каталога не проверялись: подтверждение кода выполняет владелец аккаунта. Получение кода от настоящего сервера Яндекса проверено.
- API Яндекса неофициальный. Поддержаны старый `download-info` и подписанный `get-file-info` для MP3. Изменения сервиса могут потребовать правок.
- Первая страница поиска; нет обложек, FLAC/AAC, текстов песен, эквалайзера, трея и офлайн-библиотеки. Системные медиаклавиши добавлены на Android; на Windows добавлены в 0.4.0.
- Это самостоятельный минимальный интерфейс, а не полная копия официального приложения.
- Меньше памяти или быстрее Rust-версии пока не доказано.

## Оффлайн-плейлисты

Вкладка «Оффлайн»: создание локальных плейлистов, сохранение отдельных треков или списка. По умолчанию музыка сохраняется в «Оффлайн». Скачанные MP3 играют без сети и входа; одна копия файла используется несколькими списками. Подробности и ограничения: [OFFLINE.md](OFFLINE.md).

В «Моей волне» кнопка «Обновить» запрашивает новый список без остановки текущей музыки. Новый список становится очередью после выбора трека.

## Волна и FLAC — 0.11.0

В режиме «Все» общие настройки сохранены, а отдельные группы Яндекса и Звука доступны рядом: иностранный язык и музыка без слов Яндекса, независимые энергия и настроение Звука. Числовые параметры Звука выбираются с шагом 10%. Жанры можно отмечать по несколько (до 32 на сервис), выбор сохраняется в профиле. «Любой» очищает выбор; «Применить» запускает новую волну. Полные списки показываются страницами без прокрутки; сохраняются только названия и идентификаторы, без обложек.

Меню «Трек» запускает волну по треку, исполнителю или альбому; для открытого плейлиста Звука доступно радио плейлиста. Радио выбранной сущности использует её сервис, включая режим «Все»; посторонняя персональная волна другого сервиса не подмешивается. «Применить» в настройках возвращает подборку по настройкам.

Качество: Basic, HQ и FLAC. FLAC запрашивается как отдельный исходный формат без незаметной замены на MP3; доступ зависит от трека и подписки. При отказе на переключение текущий трек продолжает играть. Декодер написан на Go, читает кадры постепенно, пропускает картинки и сохраняет прежние ограничения временного файла 256 МиБ и PCM-буфера 250 мс. Выход плеера остаётся stereo PCM 16 бит / 44,1 кГц: это поддержка исходных FLAC-файлов, а не режим bit-perfect/Hi-Res. При сохранении оффлайн хранится исходный файл, формат определяется по содержимому.

В 0.11.1 общая настройка языка включает «Без слов»: Яндекс получает свой фильтр, Звук — язык «любой» и вокал 0%. При выборе «Любой» или «Русский» вокал возвращается к 100%. «Иностранный» в общей волне использует только Яндекс. Основная страница показывает общие группы; точные настройки раскрываются кнопкой «Дополнительно» прямо на странице.

В 0.11.3 найденные треки получили отдельную кнопку ↓, которая сохраняет трек без запуска воспроизведения. Новые оффлайн-файлы называются «Исполнитель - Название.mp3» или «.flac»; недопустимые символы очищаются, совпадения получают числовой суффикс. Старые файлы с хешем в имени остаются доступными. Кнопка «Новая!» выделяется основным цветом при доступном обновлении.
