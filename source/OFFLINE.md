# Оффлайн-плейлисты — 0.7.0

Откройте вкладку «Оффлайн», создайте плейлист или используйте готовый «Оффлайн». Для сохранения трека нажмите ↓ справа от него либо «Трек ↓» для текущей песни. «Список ↓» ставит весь открытый список в очередь.

«В: …» выбирает, куда сохранять. Если ничего не выбрано, используется «Оффлайн». При открытии локального плейлиста он становится выбранным местом сохранения. После нового запуска выбор снова начинается с «Оффлайн». Создание плейлиста в окне выбора сразу выбирает его.

Сохранённые треки воспроизводятся из файлов без входа и без соединения с сервером. Один MP3 используется всеми локальными плейлистами, в которые он добавлен; повторное добавление не скачивает копию. Для скачивания нового файла нужен вход и доступ к полному MP3 Яндекса. Предпрослушивания не используются.

Загрузки последовательные, показываются имя трека, прогресс и остаток очереди. «Отмена» отменяет текущую и ожидающие загрузки; уже сохранённые треки остаются. Список пополняется после завершения HTTP-загрузки, проверки длины, первого MP3-кадра и атомарного сохранения каталога. Частичные файлы не показываются и удаляются после отмены или при следующем запуске.

При воспроизведении SHA-256 локального файла проверяется в фоновом аудиопотоке. Пауза, перемотка, шафл, медиаклавиши и восстановление очереди/позиции после перезапуска работают с локальными файлами. Качество фиксируется при постановке в очередь. Basic/HQ применяется к новым загрузкам; уже сохранённый MP3 не перекодируется и автоматически не заменяется.

Кнопка × у локального трека открывает подтверждение удаления из плейлиста. Если файл используется другим плейлистом, он остаётся. Последняя ссылка удаляет файл; если Windows держит его открытым, удаление повторяется позднее. Удалённые из активного локального плейлиста треки исключаются из его очереди.

## Где лежат файлы

Windows: `state/offline/audio/*.mp3` рядом с EXE; каталог плейлистов — `state/offline/library.json`. При использовании --state берётся указанный каталог.

Android: приватные данные приложения, тот же подкаталог offline. Дополнительного разрешения на общую память телефона не требуется. Обновление APK поверх старого сохраняет эти данные. Удаление приложения удаляет его приватные файлы. Выход из аккаунта сам по себе локальные плейлисты не очищает.

MP3 имеют безопасные имена по хешу ID трека. Названия и исполнители хранятся в каталоге. OAuth-токены и адреса аудиопотоков в него не записываются. Файлы не загружаются в Git или архив исходников.

Если SHA-256 файла не совпал, воспроизведение блокируется. Уберите повреждённый трек из всех локальных плейлистов и скачайте его заново. Отсутствующий файл можно повторно скачать, сохранив существующие ссылки в плейлистах.

## Ограничения

До 256 плейлистов, 2000 треков в одном плейлисте, 20 000 сохранённых треков суммарно, до 256 MiB на файл. Каталог ограничен 16 MiB. Загрузка не декодирует весь файл в RAM; рабочий буфер 64 KiB.

Очередь незавершённых загрузок не сохраняется при полном закрытии или убийстве процесса: её нужно поставить заново. Отдельный Android download service в этой версии не добавлен; система может прервать загрузку в фоне. Для надёжного завершения оставьте приложение открытым. Завершённые файлы и плейлисты сохраняются.

Локальная музыка доступна пользователям этого же профиля ОС, даже после выхода из Яндекса. Экспорт в общую папку Android, M3U и импорт внешних файлов пока не добавлены.

## Проверки

Автотесты: плейлист по умолчанию, именованные списки, один файл для нескольких списков, повторное добавление, повреждённый каталог, ошибка записи каталога, отмена очереди, обрыв HTTP, неверный MP3, превышение размера, отсутствие OAuth на CDN, воспроизведение настоящего MP3 при закрытом сервере и без аккаунта, восстановление локального checkpoint, SHA-256 и отмена чтения.

В нативном phone preview проверены создание «Поезд», добавление уже сохранённого трека без аккаунта, наличие одной копии MP3 в двух плейлистах, локальное воспроизведение и запись позиции/плейлиста. Последующие проверки геометрии панелей выполнялись без нативного окна. Визуальная проверка финальных бинарных сборок отдельно не выполнялась. Физический Android с этой функцией отдельно не проверен.

В 0.7.1 кнопки ↓ и × отделены от области воспроизведения строки. Нажатие на них не запускает песню и не сбрасывает её позицию.
