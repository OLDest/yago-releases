# Память и размер — 0.8.0

Без новых зависимостей. Страницы поиска/альбомов/исполнителей заменяются, максимум 40 полных моделей; история хранит максимум 200 компактных идентификаторов. Подсказки запрашиваются по нажатию, максимум пять. Новые ответы API ограничены 2 MiB; неактуальные запросы отменяются и их результаты отбрасываются. Нет обложек, изображений настроек, фонового опроса истории или поиска.

200 последовательных страниц с уникальными названиями: после GC осталось 25 440 дополнительных байт. Это проверка удержания данных страниц, не полного working set плеера. Декодирование тестового ответа поиска из двух песен: 2 292 B/op, 26 allocations/op, около 8 мкс на этой машине.

Профили выявили загрузку дополнительного системного шрифта из-за нового символа меню. В новых меню использован ASCII; лишняя загрузка устранена.

Нативный Windows GUI, одинаковый демо-сценарий и локальная версия Go с прежней правкой BSS; снимки после GC, по одному запуску каждой версии. Тестовый EXE содержит инструменты профилирования и не равен релизному по размеру.

В этих снимках Go heap стабилен и ниже исходной версии. Working set включает графику, шрифты и Windows; эти числа не являются гарантией одинакового расхода RAM на других устройствах или при воспроизведении. Сравнение показывает отсутствие роста в этом коротком сценарии, а не доказательство отсутствия всех возможных утечек.

## 0.8.2

Новые runtime-зависимости не добавлены. Иконка перед названием — готовый RGBA 32×32 (4096 байт), общий ImageOp создаётся один раз; мастер-изображение и PNG-декодер не загружаются. Удалён неиспользуемый UI-код отдельных подсказок и выбора типа. Объединённый поиск ограничен 40 моделями на категорию (максимум четыре категории); страницы и dropdown не накапливаются.

Относительно 0.8.1 EXE увеличился на 13 312 байт, APK — на 4096 байт. Проверка нулевой BSS: 375 008 байт, без возврата статического 32 MiB буфера. Новое измерение полного working set для 0.8.2 не проводилось; выше приведены измерения версии 0.8.0.

## 0.9.0: буфер волны

Фоновый загрузчик держит до 15 моделей и их session/batch; только один worker. Обычная очередь после пополнения около 25 записей, жёсткий предел 64, прошлая история — пять песен. Старые метаданные освобождаются при пополнении. Аудиофайлы будущих песен не предзагружаются в RAM. Существующий тик приложения используется для повторов с задержкой; новых таймеров и runtime-зависимостей нет. Подробности и проверки — WAVE_BUFFER.md.
